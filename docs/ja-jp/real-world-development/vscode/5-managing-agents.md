GitHub Copilot をエージェントモードにすると、コードベースを調べ、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、マシン上でリアルタイムに実行される作業を確認でき、ツール呼び出しやファイル編集の状況が表示されます。エディターを離れずに、差分を確認して個々の変更を適用または取り消し、追加のプロンプトで作業を調整・拡張できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して適用します。
- 進行中のセッションでエージェントの方向を調整し、ハイコントラストに加えてライトモード切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードの切り替え機能も追加したいとのことです。新しい会話を最初から始めずに、既存のセッションで作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集など、各ステップが表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を適用します。
   - **Undo** を選択すると変更を取り消し、別の方法で再度作業するようエージェントに任せます。
4. チャットの上部にある **Files changed** を開き、このセッション中にエージェントが変更したファイルをすべて確認することもできます。

> [!NOTE]
> ツール呼び出し (ターミナルコマンドの実行など) の許可を求められると、エージェントは一時停止して **Allow** を表示します。許可するコマンドは、内容を確認してから選択してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の要約が表示されます。

## エージェントをガイドしてライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントは前の作業で使ったコンポーネント、スタイル設定の方法、ローカルストレージのパターンなどのコンテキストを保っています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントはこれまでの変更を確認し、ライトモードの追加を提案します。
3. ハイコントラストモードのときと同じように、新しい編集をひとつずつレビューし、各差分で **Keep** または **Undo** を選択します。
4. エージェントの進め方が希望と異なる場合 (たとえば、好みでない方法でトグル UI をリファクタリングする場合) は、チャット入力欄の隣にある **Stop** ボタンを選択して停止し、追加のメッセージで意図を説明します。

> [!TIP]
> 作業中のセッションで方向を調整する方が、最初からやり直すよりも早く進められます。追加のプロンプトで変更を依頼できます。たとえば、「CSS を簡素化して、セレクターの重複ではなく CSS 変数を使う」、方向を修正するために「トグルを 3 つに増やさず、既存の設定パネルにライトモードを組み込む」、範囲を広げるために「両方のトグルにキーボードショートカットも追加する」と指示できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容をすべて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更したファイルをいくつか開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保存など) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、進行中のセッションを監視し、方向を調整しました。ファイル編集を確認しながら適用または取り消し、コンテキストを失わずに追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を適用または取り消しました。
- 追加プロンプトで進行中のセッションを調整しました。
