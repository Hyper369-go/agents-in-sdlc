**[GitHub Copilot アプリ][about-copilot-app]** は、エージェント駆動の開発に使うデスクトップアプリケーションです。GitHub Copilot CLI を基盤とし、GitHub とネイティブに連携するため、リポジトリ、ブランチ、CI パイプラインをすぐに利用できます。複数のエージェントをそれぞれ独立したワークスペースで並行して動かすワークフローに適しています。作業をすべて自分で行うのではなく、エージェントに指示して反復タスクを自動化できます。Node.js のインストールとプロジェクトの準備ができたので、次はアプリをインストールしてリポジトリを接続します。

このレッスンでは、次のことを行います。

- GitHub Copilot アプリをインストールしてサインインします。
- GitHub リポジトリからプロジェクトをアプリに追加します。
- バックログを含むワークスペースの使い方を確認します。
- アプリについて質問する簡単なチャットを試します。

## シナリオ

チームでは、増え続けるバックログに取り組むために AI エージェントを使い始めています。Copilot アプリを使うと、Issue の選択、エージェントの実行、変更のレビュー、プルリクエストのマージなどをひとつの場所で管理できます。このレッスンでは、アプリをインストールしてリポジトリを接続し、プロジェクトについての会話を始める方法を学びます。

> [!NOTE]
> Copilot Free、Copilot Student、または有料プラン (Pro、Pro+、Business、Enterprise) など、対象となる Copilot プランが必要です。Copilot Business または Copilot Enterprise を使う場合、管理者が **GitHub Copilot app** ポリシーを有効にしている必要があります。

## GitHub Copilot アプリをインストールして設定する

GitHub Copilot アプリを使うには、まずインストールします。Windows、macOS、Linux 用のバージョンがあります。アプリをインストールして認証し、Tailspin Toys リポジトリを追加しましょう。

1. ブラウザーで [GitHub Copilot アプリのランディングページ][download-app]を開きます。
2. 使用するプラットフォーム向けのアプリをダウンロードし、ランディングページの手順に従ってインストールします。
3. インストール後、アプリを開きます。
4. **Sign in to GitHub** を選択し、画面の指示に従って認証します。データ所在地が有効な GitHub Enterprise Cloud を使う場合は、**Use GitHub Enterprise** を選び、求められたら `*.ghe.com` のホスト名を入力します。GitHub Enterprise Server には対応していません。
5. オンボーディングでリポジトリを選ぶ場合は、テンプレートから作成した Tailspin Toys リポジトリを選択します。リポジトリの選択をスキップし、オンボーディング後に追加することもできます。
6. テーマを選ぶよう求められた場合は選択し、オンボーディングを完了します。
7. サイドバーの **Sessions** の下にリポジトリが表示されていることを確認します。すでに表示されている場合は、もう一度追加する必要はありません。
8. まだ接続されていない場合は、**Sessions** の横にある **+** を選択して新しいセッションを作成し、**Add GitHub repository** を選びます。前提条件のレッスンで控えた所有者名とリポジトリ名を入力します。
9. サイドバーにリポジトリが表示されることを確認します。この画面では、`tailspin-toys` などのリポジトリフォルダーが **Sessions** の下にまとめられ、その下に個別のセッションが表示されます。

## ワークスペースの使い方を確認する

プロジェクトを接続したら、ワークスペースの構成を確認しましょう。サイドバーには主に次の項目があります。

- **New** - 新しい Copilot チャットセッションを開始します。
- **Pull requests** - アプリの GitHub ネイティブ連携を通じて、プルリクエストを表示します。アプリを離れずに、一覧の閲覧とフィルタリング、CI の状態確認、レビューを行えます。
- **Issues** - 同様に連携された Issue を表示します。一覧を閲覧してフィルタリングし、Issue からセッションを開始できます。
- **Automations** — スケジュールまたはオンデマンドで実行するエージェントタスクを保存します。ToDo リストの管理、定期的なプロジェクト保守、または任せたい反復作業に役立ちます。このワークショップでは演習ではなく、次のステップとして紹介します。
- **Customize** - MCP サーバー、プラグイン、スキルなどのコンポーネントを追加して、Copilot アプリの機能を拡張します。Playwright MCP の設定に使います。
- **Chats** — ブランチや専用のワークスペースを必要としない、質問やアイデア出しのための簡単な会話です。最初のチャットを開始すると表示されます。表示されていない場合は、**Sessions** の横にある **+** を選択してチャットを開始します。
- **Sessions** — リポジトリフォルダーと、その中のエージェントセッションをまとめます。`tailspin-toys` などのリポジトリ名を選ぶとリポジトリビューが開き、その下のセッションを選ぶとその会話に戻ります。各セッションは独立したワークスペースで動くため、変更が競合せずに複数の作業を並行できます。星評価を追加する際に最初のセッションを開始します。

ワークショップを進めながら、ワークスペースの使い方を確認していきます。

> [!TIP]
> 迷ったら Copilot に質問してください。操作方法が分からない場合や、その操作が可能か確認したい場合は、Copilot が案内してくれます。

### 登録済みのバックログを確認する

バックログのないプロジェクトはほとんどありません。Tailspin Toys も例外ではありません。テンプレートの作成時に用意されたバックログを確認しましょう。

1. サイドバーの **Sessions** の下にある Tailspin Toys リポジトリフォルダーを選択します。その下の個別セッションではありません。次に、リポジトリの上部ナビゲーションで **Issues** を選択します。
2. Issue 番号を前提にせず、タイトルで次の Issue を探します。

   - Allow users to filter games by category and publisher
   - Update our repository coding standards

3. Issue を選択して詳細を読みます。各 Issue からエージェントセッションを開始できます。最初の小さな変更を終えた後、フィルター機能の Issue から作業を始めます。

> [!NOTE]
> **Issues** と **Pull requests** の一覧には、Copilot アプリに追加したリポジトリの項目だけが表示されます。他のリポジトリの作業項目も確認する場合は、そのリポジトリをアプリに追加してください。

## 簡単なチャットを試す

アプリの使い方に慣れるために、*アプリ自体*について質問してみましょう。**簡単なチャット**を使うと、ブランチやワークツリーを作らずに質問やアイデア出しができます。セッションを作る必要のない、気軽な質問に適しています。

1. サイドバーの **Chats** の横にある **+** を選択し、新しいチャットを開きます。**Chats** がまだ表示されていない場合は、**Sessions** の横にある **+** を選択して最初のチャットを開始します。その後 **Chats** が表示されます。
2. アプリ自体のセッションの仕組みについて質問します。

   ```plaintext
   How does the GitHub Copilot app use worktrees?
   ```

3. 会話ビューで応答を読みます。各セッションは独立した Git ワークツリーで実行されます。これにより、変更が競合せず複数のエージェントを並行して動かせます。会話は続けても、新しいチャットを始めてもかまいません。

## まとめと次のステップ

GitHub Copilot アプリをインストールしてプロジェクトを接続し、ワークスペースを確認できました。次のことを学びました。

- アプリをインストールして GitHub にサインインする。
- GitHub リポジトリからプロジェクトを追加する。
- ワークスペースの使い方を確認し、**Issues** で登録済みのバックログを探す。
- 簡単なチャットで気軽な質問をする。
